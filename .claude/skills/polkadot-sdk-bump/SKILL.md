# Bump polkadot-sdk & Regenerate Codegen

Moves the `polkadot-sdk` pin to a newer commit and reconciles everything that depends on it:
the `Cargo.lock` revision, the committed subxt codegens, the relay-client version guards, and the
zombienet-sdk integration tests.

## What the bump touches

1. **The pin** — the `polkadot-sdk` git commit in `Cargo.lock` (and, in this repo, the git deps in
   the root `Cargo.toml`).
2. **Two codegen families**, both generated by `scripts/generate-codegen.sh` from runtime WASM:
   - `testing/zombienet-sdk-tests/tests/codegen/*.rs` — `--full` subxt clients the tests consume.
   - `relay-clients/client-*/src/codegen_runtime.rs` — `runtime_types`-only clients the relay is
     built against.
3. **Version guards** — the hand-maintained `RUNTIME_VERSION` (`spec_version` / `transaction_version`)
   const in each `relay-clients/client-*/src/lib.rs`. The relay aborts against a chain whose runtime
   version doesn't match, so these must track the runtimes.
4. **Validation** — `cargo check`/`clippy`, the `check-codegen-compat.py` gate, and the zombienet-sdk
   tests.

Only the **rococo/westend family** lives in polkadot-sdk (`rococo`, `westend`, `asset-hub-rococo`,
`asset-hub-westend`, `bridge-hub-rococo`, `bridge-hub-westend`). Kusama/Polkadot/Bulletin runtimes
ship from the Fellows `runtimes` repo — they are **not** regenerated from a polkadot-sdk checkout
(see the release workflow / `--wasm-file` for those).

## Prerequisites

- A local `polkadot-sdk` checkout (default assumed at `../polkadot-sdk`).
- `wasm32-unknown-unknown` target (for building runtime WASM) and **nightly rustfmt** (codegen
  formatting): `rustup target add wasm32-unknown-unknown`.
- For the tests: Docker (default provider) **or** locally built `polkadot`/`polkadot-parachain`
  binaries (native provider). See Step 7.

## Step 0 — Locate the polkadot-sdk checkout

Ask the user for the checkout path (`POLKADOT_SDK_PATH`, default `../polkadot-sdk`). To bump to the
tip of a branch, update it first:

```bash
git -C "$POLKADOT_SDK_PATH" fetch origin
git -C "$POLKADOT_SDK_PATH" checkout master && git -C "$POLKADOT_SDK_PATH" pull
```

To bump to a specific commit instead, `git -C "$POLKADOT_SDK_PATH" checkout <sha>`.

## Step 1 — Determine the new revision

```bash
NEW_HASH="$(git -C "$POLKADOT_SDK_PATH" rev-parse HEAD)"; echo "$NEW_HASH"
```

The repo's single source of truth for the *current* pin is `scripts/polkadot-sdk-rev.sh` (it reads
the `polkadot-sdk?branch=master#<hash>` source out of `Cargo.lock`; the zombienet CI and codegen
script share it):

```bash
OLD_HASH="$(scripts/polkadot-sdk-rev.sh)"; echo "$OLD_HASH"
```

## Step 2 — Update the pin in Cargo.toml / Cargo.lock

**Normal (git master) mode** — the deps point at `git+https://github.com/paritytech/polkadot-sdk`:

```bash
# Rewrite the locked commit for every polkadot-sdk git source in one shot.
sed -i "s/${OLD_HASH}/${NEW_HASH}/g" Cargo.lock
grep -c "${NEW_HASH}" Cargo.lock                     # sanity: should be > 0
# Let cargo re-resolve the graph against the new commit and rewrite Cargo.lock consistently,
# then confirm it needs no further changes.
SKIP_WASM_BUILD=1 cargo check --workspace
SKIP_WASM_BUILD=1 cargo check --locked --workspace
```

If the workspace pins the branch in the root `Cargo.toml` (`{ git = "…polkadot-sdk", branch = "…" }`),
leave the branch as-is and let `Cargo.lock` carry the commit; only touch `Cargo.toml` if the *branch*
or source URL changes.

> **Local-checkout override mode.** If the root `Cargo.toml` redirects polkadot-sdk deps to a local
> checkout (`git = "file:///…/polkadot-sdk", branch = "…"`) — a common dev setup for in-flight
> polkadot-sdk changes — there is **no `branch=master#…` line** in `Cargo.lock`. In that mode
> `scripts/polkadot-sdk-rev.sh` exits 1 (see the Gotchas), and the "bump" is done by moving the local
> checkout to the new commit + `cargo update`, not by editing a hash. You'll then pass
> `--polkadot-sdk-hash` explicitly in Step 3.

## Step 3 — Regenerate both codegen families

`scripts/generate-codegen.sh` builds the six runtimes' WASM from the checkout, runs
`tools/runtime-codegen`, applies the `Header<u32>` → `Header<u32, BlakeTwo256>` fixup, and formats
with nightly rustfmt. Run **both** targets:

```bash
scripts/generate-codegen.sh --target zombienet     --polkadot-sdk "$POLKADOT_SDK_PATH"
scripts/generate-codegen.sh --target relay-clients --polkadot-sdk "$POLKADOT_SDK_PATH"
```

- Without `--polkadot-sdk`, the script clones polkadot-sdk at the `Cargo.lock` pin into
  `target/polkadot-sdk-codegen` and builds it there.
- To force a specific commit regardless of the checkout's branch, add `--polkadot-sdk-hash <sha>`.
- **In local-override mode you MUST pass `--polkadot-sdk-hash <sha>`** (any value, e.g. the checkout
  HEAD) — it bypasses the failing `polkadot-sdk-rev.sh` call that would otherwise abort the script
  before it does anything.

Review the diff. If a codegen comes back changed **only** in the `EXECUTED COMMAND` header comment,
the runtime types didn't actually change for that target — `git checkout --` those files rather than
committing machine-path noise. Real type changes (hundreds/thousands of non-comment lines) are the
substantive update and should be committed.

```bash
git diff --stat testing/zombienet-sdk-tests/tests/codegen/ relay-clients/*/src/codegen_runtime.rs
```

## Step 4 — Refresh the relay-client version guards

Each runtime declares a `RuntimeVersion { spec_version, transaction_version, .. }` in its `lib.rs`.
Read the new values from the checkout and copy them into the matching relay-client's
`RUNTIME_VERSION` const.

Runtime → relay-client map (rococo/westend family):

| relay-client | runtime `lib.rs` in polkadot-sdk |
|---|---|
| `client-rococo` | `polkadot/runtime/rococo/src/lib.rs` |
| `client-westend` | `polkadot/runtime/westend/src/lib.rs` |
| `client-asset-hub-rococo` | `cumulus/parachains/runtimes/assets/asset-hub-rococo/src/lib.rs` |
| `client-asset-hub-westend` | `cumulus/parachains/runtimes/assets/asset-hub-westend/src/lib.rs` |
| `client-bridge-hub-rococo` | `cumulus/parachains/runtimes/bridge-hubs/bridge-hub-rococo/src/lib.rs` |
| `client-bridge-hub-westend` | `cumulus/parachains/runtimes/bridge-hubs/bridge-hub-westend/src/lib.rs` |

Read the new values, then edit each guard:

```bash
# new values (from the checkout)
grep -rn "spec_version:\|transaction_version:" --include=lib.rs \
  "$POLKADOT_SDK_PATH"/polkadot/runtime/{rococo,westend}/src/lib.rs \
  "$POLKADOT_SDK_PATH"/cumulus/parachains/runtimes/assets/asset-hub-{rococo,westend}/src/lib.rs \
  "$POLKADOT_SDK_PATH"/cumulus/parachains/runtimes/bridge-hubs/bridge-hub-{rococo,westend}/src/lib.rs

# current guards (to update)
grep -rn "SimpleRuntimeVersion" relay-clients/*/src/lib.rs
```

Update the `spec_version` **and** `transaction_version` in each
`Some(SimpleRuntimeVersion { spec_version: …, transaction_version: … })`. Leave the
Kusama/Polkadot/Bulletin clients alone (their runtimes aren't in this checkout).

## Step 5 — Compile & lint

```bash
SKIP_WASM_BUILD=1 cargo check --locked --workspace
SKIP_WASM_BUILD=1 cargo clippy --all-targets --locked --workspace
cargo +nightly fmt --all
```

Resolve any dependency-version mismatches by aligning the workspace `Cargo.lock` with polkadot-sdk's
(the usual suspects are shared third-party crates). `correctness` and `complexity` clippy groups are
denied — those must be clean.

## Step 6 — Codegen compatibility gate

The zombienet CI runs this before the ~30-min build; run it locally to fail fast:

```bash
python3 scripts/check-codegen-compat.py --verbose
```

It asserts the zombienet (`--full`) and relay-clients (`types-only`) codegens haven't drifted into
SCALE-incompatible bridge types. If it fails, you regenerated only one target in Step 3 — rerun both.

## Step 7 — Validate with the zombienet-sdk tests

The tests live in `testing/zombienet-sdk-tests/` (crate `bridges-zombienet-sdk-tests`), are gated by
the `zombie-ci` feature, and cover the **Rococo ⇄ Westend** bridge:

- `rococo_westend::asset_transfer` — assets cross the bridge both directions; free-header relayers'
  balances stay constant;
- `rococo_westend::free_headers` — free relay/parachain headers sync to the remote Bridge Hub while
  the relayer is otherwise idle.

The codegens under `tests/codegen/` must match the runtimes in the node binaries you run (i.e. the
pinned polkadot-sdk revision), or subxt aborts with
`Metadata error: The generated code is not compatible with the node`. That's exactly what Step 3
keeps in sync.

**Build the prerequisites** (from the polkadot-sdk checkout — `polkadot` produces `polkadot`,
`polkadot-prepare-worker`, `polkadot-execute-worker`; keep all three together):

```bash
( cd "$POLKADOT_SDK_PATH" \
  && cargo build --release -p polkadot --features fast-runtime \
  && cargo build --release -p polkadot-parachain-bin )

cargo build --release -p substrate-relay
export SUBSTRATE_RELAY_BINARY="$PWD/target/release/substrate-relay"
```

**Pick a node provider:**

- `native` — run the binaries you just built from `PATH` (simplest locally):

  ```bash
  export ZOMBIE_PROVIDER=native
  export PATH="$POLKADOT_SDK_PATH/target/release:$PATH"
  ```

- `docker` (default) — pulls `paritypr/polkadot-debug` / `polkadot-parachain-debug` tagged with the
  pinned short (8-char) revision (defaults set by `build.rs` from `Cargo.lock`; override with
  `POLKADOT_IMAGE` / `CUMULUS_IMAGE`). The image tag for the bumped revision must exist in the
  registry.

**Run** (one test, or the whole suite; keep `--test-threads=1` — each test spawns full
Rococo+Westend networks):

```bash
cargo test -p bridges-zombienet-sdk-tests --features zombie-ci asset_transfer -- --nocapture --test-threads=1
cargo test -p bridges-zombienet-sdk-tests --features zombie-ci free_headers   -- --nocapture --test-threads=1
cargo test -p bridges-zombienet-sdk-tests --features zombie-ci                -- --nocapture --test-threads=1
```

On success a test exits `0`; on failure it dumps node + relayer logs. You can also trigger the
`Zombienet Tests` GitHub workflow (`.github/workflows/zombienet.yml`, `workflow_dispatch` or a
same-repo PR) to run the suite in CI on `parity-large` runners.

> **Scope:** the zombienet-sdk suite currently implements **only Rococo ⇄ Westend** (see the crate's
> `tests/rococo_westend/`); a second bridge pair would be added as a sibling module. Don't invent a
> Polkadot ⇄ Kusama zombienet-sdk test that doesn't exist — treat it as out of scope unless the suite
> has grown one.

## Step 8 — Report

Summarize: old → new revision; which codegens actually changed (vs comment-only no-ops reverted);
the spec/transaction_version guard changes per client; check/clippy/compat results; and the
zombienet test outcomes. Commit the regenerated codegens, the `Cargo.lock`/`Cargo.toml` pin, and the
version-guard edits together.

## Gotchas

- **`generate-codegen.sh` aborts immediately in local-override mode.** With a `file://` polkadot-sdk
  override there's no `branch=master#<hash>` in `Cargo.lock`, so `polkadot-sdk-rev.sh` exits 1 and
  `set -euo pipefail` kills the script right after the `>> target=…` line — it looks like "no change"
  but nothing ran. Fix: pass `--polkadot-sdk-hash <sha>` (the value is unused when `--polkadot-sdk`
  is given, since no clone happens).
- **Regenerate BOTH targets.** `--target zombienet` and `--target relay-clients` write different
  files; updating only one trips `check-codegen-compat.py`.
- **Comment-only codegen diffs.** Running the script from a different working directory rewrites the
  `EXECUTED COMMAND` doc-comment with absolute paths. If that's the *only* change, revert the file —
  don't commit machine paths. It also means the runtime types were already current for that target.
- **WASM variant is irrelevant.** The checkout-build path uses the uncompressed
  `<chain>_runtime.wasm`; the tool (`WasmTestBed`) transparently handles the
  `.compact.compressed.wasm` too, and both yield identical metadata. Fellows release blobs (the
  `.compact.compressed.wasm`) are only used via `--wasm-dir`/`--wasm-file` for the non-SDK chains.
- **Version guards are hand-maintained** — codegen does not update them. A stale guard makes the
  relay abort against the upgraded chain; a stale codegen makes subxt reject the metadata. Both must
  move together with the bump.
- **`SKIP_WASM_BUILD=1` for repo checks only.** Use it for `cargo check`/`test`/`clippy` in *this*
  repo; never set it when building runtime WASM or node binaries in the polkadot-sdk checkout — that
  would skip the very artifacts you need.
- **`subxt` pin.** `subxt`/`subxt-signer` are pinned in the workspace `Cargo.toml` to the version
  `zombienet-sdk` uses. If a bump drags in a new `zombienet-sdk`, realign `subxt` to match, or
  `node.wait_client()` returns the wrong client type.
